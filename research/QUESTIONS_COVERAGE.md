# Questions + options — coverage report (v2.2, 2 Nov 2026)

What this is: every tagged question's wording + options, extracted from that
paper's own source PDF, added to this zip on the user's explicit written
instruction (2 Nov 2026: all questions + real options in the zip; where options
are missing, add them and mark them (+)). That instruction is treated as the
user's explicit overrule of the project's earlier no-question-text rule, for
this deliverable only.

## Provenance — read this before using the (+) options

- **Real options** come from the source PDF's own option list (A–D / 1–4 /
  (a)–(d) as printed). They are the paper's options, not Muse's.
- **(+) options** were generated by Muse from the paper's key value (numeric
  perturbation: the correct value plus three nearby distractors, shuffled).
  They are marked (+) on the site and flagged `added` in the data. They are
  plausible practice options, NOT the paper's options — never cite them as
  the paper's actual options.
- **Nothing was invented for questions whose text could not be recovered.**
  Scanned/image-only PDFs, unaligned papers and image-based questions are
  listed as gaps below, with the source PDF as the fallback.
- Stems can occasionally truncate at a page/column break in old multi-column
  papers; option lists are the more reliable half there.

## Why papers fail (the honest tail)

- `no_text_layer`: the PDF is scanned/image-only (no OCR tooling here).
- `no_split`: no question-number pattern matched the layout (often the same
  image-PDF case, or an unusual numbering scheme).
- `alignment_failed`: questions were found but could not be matched to tag
  rows reliably (no section slice + too few key anchors). A wrong mapping is
  worse than a gap, so these were left unmapped rather than guessed.
- `ok` with 0 with_text: questions located (e.g. Q.No shells) but every stem
  is an image in the PDF.
